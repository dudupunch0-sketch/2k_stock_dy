# 제작안: 두루미 주식 분석·주간 투자 기록

상태: 구현 전 검토안. 데이터 접근 확인과 비밀값 보관은 완료했으며 프로그램·예약 작업은 아직 제작하지 않았다.

## 목표와 사용 흐름

사용자는 ChatGPT Work에서 종목을 요청하거나 관심·보유 목록을 관리한다. 프로그램은 근거 자료와 수치를 정리하고, Luna medium은 해석과 시나리오를 작성한다. 공통 생성기가 인터랙티브 HTML을 만들고 공개 저장소에 날짜별 기록을 남긴다.

첫 실제 사례는 장기 보유 중인 에이피알(278470)이다. 추가매수·분할매도를 검토할 가격·실적·위험 조건을 제공하고 최종 매매 판단은 사용자가 한다. 보유수량이 없는 상태에서 매매수량을 추정하지 않는다.

자료 수집(GitHub Actions) -> 정규화된 근거 자료 -> 해석(ChatGPT Work) -> HTML 생성·기록

## 선택한 접근과 최소 제품

- Python 3.12와 표준 라이브러리 중심으로 수집·검산·HTML 생성을 구현한다. 화면은 HTML/CSS/JavaScript로 구성하고 실행에 별도 웹서버를 요구하지 않는다.
- Work에서 이미 사용하는 AI로 분석한다. 별도 유료 AI API 호출이나 상시 서버는 기본 구성에 포함하지 않는다.
- GitHub Actions가 DART_API_KEY 비밀값을 실행 환경변수로 받아 공시를 수집한다. Work나 보고서가 GitHub 비밀값 원문을 읽을 필요는 없다.
- Work는 GitHub 연결로 요청 JSON을 저장한다. 요청 경로의 변경으로 수집 작업이 실행되며 완료 기록과 자료가 저장된다. Work는 완료된 자료를 받아 분석한다.
- 수집 요청은 종목·기간·요청 ID를 명시한다. 중복 요청을 재사용하고 자료 수집 실패를 보고서에 표시한다.
- 최초 제품은 에이피알 한 종목을 요청해 실제 근거가 포함된 HTML을 받고 보관하는 흐름이다. 이 단계만으로도 수동 상세 분석 도구로 사용할 수 있다.
- 별도 대시보드 서버나 매번 AI가 웹사이트 전체를 다시 만드는 방식은 초기 규모와 반복 사용 목적에 비해 유지 비용이 커 채택하지 않는다.
- public GitHub에 날짜별 HTML과 투자 기록을 남긴다. 최초 열람 방식은 Work가 전달하는 HTML 파일이다. GitHub Pages 같은 추가 호스팅은 첫 제품의 필수 의존성이 아니다.

## 자료와 계산 규칙

- 국내 확정 재무: OpenDART. 에이피알 고유번호 01190568 및 2025년 연결 재무정보 접근 확인 완료.
- 미국 확정 재무: SEC submissions/companyfacts와 원문 공시. companyfacts에 없는 사업부별 수치는 원문 공시를 확인한다.
- 사업·제품·전략: 기업 공식 사업/연차 보고서와 IR.
- 전망: 접근 가능한 개별 증권사 보고서, 기업 가이던스, 여러 기관의 컨센서스를 각각 구분한다. 한 개 보고서를 시장 전체 컨센서스로 부르지 않는다.
- 국내 증권사 보고서는 한경컨센서스를 우선 확인하고 원 발행기관 자료로 교차 확인한다. 미국은 접근 가능한 원 발행기관 보고서와 기업 가이던스를 사용한다. 열람 가능한 보고서가 부족하면 부족한 개수를 표시한다.
- 가격·시가총액·수급·검색관심도·뉴스는 Work가 출처와 기준시각을 함께 확인해 정해진 자료 형식에 기록한다. 확인할 수 없는 값을 AI가 채우지 않는다.
- 최근 완료된 5개 회계연도, 최신 공시 분기 및 누적/단독 분기를 구분한다. 공시 기준일 이후 자료를 과거 보고서에 소급 삽입하지 않는다.
- 연결/별도, 원화/달러, 단위, 회계연도, 수정 공시, 주식분할과 희석을 구분한다. 과거 연말 지표와 현재 주가를 사용한 지표를 섞지 않는다.
- 매출·이익률·증가율·FCF 등은 프로그램으로 계산한다. 적자 PER, 음의 자본 PBR 등 해석에 적합하지 않은 경우 사유와 함께 N/A로 표기한다.
- 재무제표와 시장 지표, 예상 실적의 출처 기준을 구분한다. 출처가 충돌하면 우선순위와 차이를 남긴다.
- 경쟁사 2개는 사업 구성과 수익 구조의 유사성을 근거로 제안한다. 비교 기간과 통화를 정렬하고 차이가 남으면 비교 한계를 표시한다.
- Google Trends, 원재료 단가, 5년 시장점유율 등은 산업 관련성과 자료 가용성을 먼저 평가한다. 미공개·미확인은 결측 상태로 보존한다.

## 보고서

기존 9개 분석 범위를 유지하고 다음을 공통화한다.

- 첫 화면: 3줄 요약, 기준일, 현재 확인된 가치평가 범위, 지난 분석 대비 중요한 변화, 추가 확인이 필요한 사항.
- 펼쳐 보기: 기업·산업, 재무·현금흐름, 투자포인트·위험, 장기 성장, 경제적 해자, 경쟁사, 비용·레버리지, 가치평가, IR·뉴스·보고서.
- 숫자와 중요한 주장은 출처 링크로 연결한다. 계산값은 입력값과 산식을 확인할 수 있게 한다.
- 추세·비교에 유용할 때 매출/이익/마진/현금흐름 등 차트를 표시한다. 자료가 없는 차트를 만들지 않는다.
- 에이피알의 사업 구조에 맞춰 성장률, 이익률, 지역/제품 구성, 현금흐름, 재고·마케팅비 등 확인 가능한 항목을 살핀다. 특정 사업 지표가 공개되었다고 미리 가정하지 않는다.
- 24개월 보수·기준·낙관 시나리오: 성장·마진·주식수·평가 배수 등 가정, 근거, 가치 범위, 현재 가격 대비 차이, 반증 조건.
- 기업 특성에 적합한 평가법을 선택하고 선택 이유를 기록한다. 에이피알은 이익 기반 비교를 출발점으로 현금흐름과 비교기업으로 검토한다. 가정을 바꾸는 화면은 프로그램 산식으로 재계산한다.
- 추가매수 검토는 가격과 투자 가설의 유지 여부를 함께 보여준다. 분할매도 검토는 가치평가 과열과 기업 전망 악화를 구분한다. 근거 없는 확률이나 자동 매매 명령을 출력하지 않는다.
- AI 분석과 사용자가 적은 투자 일기·매매 기록을 구분한다. 과거 보고서는 보존하고 최신판으로 연결한다.

## 재사용과 저장 계약

전체 구현은 문서·워크플로·테스트를 포함해 8개 이상의 파일을 변경하는 규모다.

- config/universe.json: 시장·종목코드·기업 식별자·보유/관심 구분. 초기 실제 등록은 에이피알만.
- requests/: 수집 요청과 해당 요청의 완료/실패 상태.
- data/: 기준일별 정규화 수치, 자료 출처, 변경 기록. 자료의 수집 시각과 공시 시각을 분리한다.
- analysis/: AI가 작성한 구조화된 분석과 시나리오 가정.
- journal/: 사용자가 작성한 투자 근거와 메모.
- reports/: 날짜별 HTML, 최신판 목록.
- stockdy/: 수집·정규화·계산·검증·HTML 생성 기능.
- templates/: 재사용 HTML/CSS/JavaScript.
- .github/workflows/: 요청에 따른 자료 수집 및 결과 저장.
- instructions/: Work의 상세 분석·주간 보고 지시문.
- tests/: 데이터·계산·보안·보고서의 의미 있는 검증.

원문 전체를 AI에 반복 입력하지 않는다. 새 자료와 이전 분석의 차이, 필요한 근거를 묶어 입력한다. 절감을 이유로 중요한 반대 증거를 버리지 않고 자료 미확인 상태를 명시한다.

## 두 번의 독립적으로 사용 가능한 납품

1. 에이피알 상세 분석: 수집 요청, DART 재무, 근거 자료 형식, 계산·시나리오, HTML 생성, 공개 기록을 연결한다. 실제 보고서를 검토할 수 있어야 이 단계가 완료된다.
2. 미국 기업과 주간 보고: 동일한 형식의 SEC 수집을 추가하고 미국 표본으로 검증한다. 보유/관심 목록의 지난 일주일 변화와 다음 주요 일정을 묶는 보고서를 만든다. Work 웹에서 금요일 한국시간 10시 시작하는 주간 실행을 설정한다.

미국 검증용 공개 표본은 Apple을 제안하되 사용자의 실제 보유/관심 명단에 추가하지 않는다. 주간 실행은 등록된 종목만 대상으로 하고 임의로 13개 종목을 채우지 않는다. 일별 감시와 실적 이벤트별 알림은 구현하지 않는다.

## 검증과 실패 처리

- DART/SEC 원문과 연간·분기 수치를 대조한다. 누적/단독 분기, 정정 공시, 결측·적자·주식분할·통화 차이를 검증한다.
- EPS 등 누적 수치의 단순 차감이 부적절한 항목을 별도로 검증한다.
- 시나리오 가정 변경과 평가값 계산을 고정 입력으로 검사한다. 출처 없이 생성된 숫자는 검증에서 실패해야 한다.
- HTML에서 요약/상세, 출처 이동, 종목 선택, 가정 변경을 브라우저로 확인한다.
- 문서 원문이나 기사에 들어 있는 지시문은 자료로 취급한다. 요청 JSON과 웹 자료가 셸 명령이나 HTML 실행 코드로 삽입되지 않게 한다.
- 키가 Git 기록·산출물·로그에 포함되지 않는지 검사한다.
- API 장애·승인 실패·최신 자료 부족은 날짜와 원인을 표시하고 마지막 성공 자료를 사용할지 명시한다. 오래된 자료를 최신으로 표시하지 않는다.
- 같은 주간 실행을 반복해도 중복 보고서를 남기지 않는다. 동시 실행의 Git 충돌을 처리하고 실패 시 기존 보고서를 보존한다.
- 사용량은 Luna medium 시범 실행 전후에 같은 5시간 구간의 계정 사용률을 비교한다. 다른 작업·한도 초기화가 섞이면 보고서당 소모율로 쓰지 않는다.
- 실제 Work 클라우드에서 GitHub 요청, 자료 회수, 생성 스크립트 실행, HTML 열람, 결과 저장을 확인한 뒤 예약을 활성화한다. 현재 로컬에서 확인한 결과를 클라우드 실행 성공으로 표시하지 않는다.
- 문제 발생 시 예약과 수집 워크플로를 중지하고 마지막 성공 보고서로 돌아갈 수 있어야 한다. 비밀값은 공개 파일과 독립적으로 교체할 수 있다.

## 필요한 연결과 현재 확인 상태

- GitHub: 저장소 파일 쓰기 권한, CLI 인증, Actions 비밀값 등록 확인 완료.
- OpenDART: 인증과 에이피알 연결 재무 조회 확인 완료.
- SEC·기업 IR: 공식 문서/자료 페이지 접근 확인. 자동 수집 경로는 구현 검증 대상.
- ChatGPT Work 클라우드: 사용자가 GitHub 연동을 완료했다고 설명했다. 이 세션에서 실제 클라우드 실행·예약은 아직 검증하지 않았다.
- 추가 유료 AI API·상시 서버는 요구하지 않는다. 데이터 부족을 해결하기 위한 유료 계약은 이 제작안에 포함하지 않는다.
